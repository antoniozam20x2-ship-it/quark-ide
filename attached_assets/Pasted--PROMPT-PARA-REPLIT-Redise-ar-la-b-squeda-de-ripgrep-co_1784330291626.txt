# PROMPT PARA REPLIT — Rediseñar la búsqueda de ripgrep con regex nativo
# (en vez de reutilizar la lógica de variantes pensada para GitHub API)

## Contexto

Ya diagnosticamos que `generateSearchVariants` + `cleanForGitHubSearch` fueron
diseñadas específicamente para GitHub Code Search API: un motor remoto que indexa
por tokens/palabras y necesita variantes discretas (camelCase, snake_case,
CONSTANT_CASE) generadas a mano porque no entiende gramática de código.

Ahora que el repo está clonado localmente y `ripgrep` es el motor primario de
búsqueda, no tiene sentido forzar esa misma lógica de "generar N variantes
discretas y probarlas". Ripgrep es un motor de regex real — puede resolver todas
esas variantes con **un solo patrón regex case-insensitive con separadores
opcionales**, en una sola pasada, sin necesidad de generar y probar strings
sueltos.

Ejemplo: en vez de generar `["trailing stop", "trailingStop", "trailing_stop",
"TRAILING_STOP", ...]` y probarlas una por una, mandar directamente el regex
`trailing[\s_-]*stop` con la flag `-i` — matchea todas esas variantes de una.

## Cambio 1 — confirmar/agregar `-i` (case-insensitive) a `rgSearch`

Revisar `services/localRepos.ts`. La función `rgSearch` actualmente arma el
comando así:

```typescript
const { stdout } = await execFileAsync(
  'rg',
  [
    '--json',
    '--max-count=5',
    '--max-filesize=2M',
    '--no-heading',
    pattern,
    dir,
  ],

```

**No tiene la flag `-i`.** Agregarla:

```typescript
const { stdout } = await execFileAsync(
  'rg',
  [
    '--json',
    '-i',                      // ← case-insensitive — nuevo
    '--max-count=5',
    '--max-filesize=2M',
    '--no-heading',
    pattern,
    dir,
  ],
  { maxBuffer: 10 * 1024 * 1024, timeout: 15_000 }
);
```

Confirmar que esto no rompe ningún caso de uso existente donde el case importe
(no debería — buscar código no suele depender de mayúsculas exactas, y de haber
una colisión el ranking de resultados sigue siendo por relevancia, no exacto).

## Cambio 2 — nueva función para armar el patrón regex de ripgrep

Agregar en `agent.ts`, cerca de `generateSearchVariants` (no reemplazarla — esa
sigue siendo necesaria para el fallback de GitHub API en el paso 3):

```typescript
/**
 * Convierte un término de búsqueda (posiblemente una frase en lenguaje natural,
 * como "trailing stop") en un patrón regex apto para ripgrep que matchea todas
 * las variantes de casing/separador de una sola vez, aprovechando -i.
 *
 * "trailing stop"  → "trailing[\\s_-]*stop"
 * "trailingStop"   → "trailingStop" (sin espacios, se devuelve tal cual — ya
 *                     matchea con -i contra TrailingStop, TRAILINGSTOP, etc.,
 *                     pero NO contra trailing_stop; para eso frases sí ayudan)
 * "circuit breaker" → "circuit[\\s_-]*breaker"
 */
function buildRipgrepPattern(term: string): string {
  const trimmed = term.trim();
  if (!trimmed) return trimmed;

  // Si el término tiene espacios (frase en lenguaje natural), insertar
  // separador opcional entre palabras: espacio, guion bajo, o guion.
  if (/\s/.test(trimmed)) {
    const words = trimmed.split(/\s+/).filter(Boolean).map(w =>
      // Escapar caracteres especiales de regex por palabra, por si acaso
      w.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
    );
    return words.join('[\\s_-]*');
  }

  // Sin espacios: si ya viene con guion/guion bajo, también permitir el
  // separador contrario y ausencia de separador (camelCase/PascalCase implícito
  // vía -i, no hace falta generar variantes explícitas de casing).
  if (/[-_]/.test(trimmed)) {
    const parts = trimmed.split(/[-_]/).filter(Boolean).map(w =>
      w.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
    );
    return parts.join('[\\s_-]*');
  }

  // Término simple sin separadores — devolver escapado tal cual
  return trimmed.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}
```

## Cambio 3 — usar `buildRipgrepPattern` en el paso 2 de `unifiedGrepSearch`

Reemplazar el paso 2 actual:

```typescript
// ── 2. ripgrep on local clone — primary search ────────────────────────────
if (isCloned(repo)) {
  const rgResults = await rgSearch(pattern, repo);
  if (rgResults.length > 0) {
    send('action', { text: `📍 ${rgResults.length} resultado(s) vía ripgrep local` });
    return rgResults.map(r => ({ path: r.path, line: r.line, text: r.text }));
  }
  return [];
}
```

Por:

```typescript
// ── 2. ripgrep on local clone — primary search ────────────────────────────
if (isCloned(repo)) {
  // Cada término (ya separados por "|" en rawTerms) se convierte en un patrón
  // regex con separadores opcionales entre palabras, y se unen de nuevo con "|"
  // para que ripgrep los busque todos en una sola pasada, con -i cubriendo el casing.
  const ripgrepPattern = rawTerms.map(t => buildRipgrepPattern(t)).join('|');
  console.log(`[unifiedGrepSearch] patrón ripgrep construido: "${ripgrepPattern}" (desde: [${rawTerms.join(', ')}])`);

  const rgResults = await rgSearch(ripgrepPattern, repo);
  if (rgResults.length > 0) {
    send('action', { text: `📍 ${rgResults.length} resultado(s) vía ripgrep local` });
    return rgResults.map(r => ({ path: r.path, line: r.line, text: r.text }));
  }
  return [];
}
```

Esto **reemplaza** el parche anterior que habíamos propuesto (el de reintentar con
`generateSearchVariants` si el primer intento fallaba) — con este enfoque no hace
falta un segundo intento, porque el regex ya cubre todas las variantes de casing
y separador en la primera pasada.
