# Prompt — Grounding literal en extractKeywordsForSearch (fix compartido: Chat, Brous, FAST, DEEP)

**Por qué esta función y no otra:** `extractKeywordsForSearch` es llamada por
`searchAndLoadFiles` (generación), por el chat-fast-path dentro de `runChatTurn`
(usado tanto por CHAT 💬 mode como por Brous 💬, que comparten el mismo backend),
y por la ruta DEEP (`/generate` con `deepMode=true`). Arreglar el grounding acá
corrige los cuatro caminos con un solo cambio, en vez de parchear cada uno por
separado.

**El bug de fondo:** el `signalOSLayer` le pide a Groq que traduzca términos de
usuario a identificadores de código SOLO si el prompt menciona el concepto
exacto (ej. "trailing" → `trailingStop`, "streak" → `circuitBreaker`). Pero
Groq generaliza por parecido semántico y devuelve la traducción igual, aunque
el trigger literal no esté en el mensaje — así "stop loss" terminó devolviendo
`circuitBreaker` (por "pérdidas") sin que el usuario mencionara rachas ni
streaks. No hay ninguna verificación de código que descarte esa traducción
espuria antes de usarla para rankear símbolos.

/** Verifica que al menos uno de los triggers literales de una traducción de
 *  dominio aparezca de verdad en el prompt del usuario — evita que Groq
 *  devuelva una traducción por parecido semántico sin el trigger real. */
function isDomainTermGrounded(term: string, prompt: string): boolean {
  const entry = SIGNAL_OS_TRANSLATIONS.find(t => t.term === term);
  if (!entry) return true; // no es un término mapeado — no aplica este chequeo
  return entry.triggers.some(re => re.test(prompt));
}

Ahorar" en Brous y en CHAT 💬 mode. Los términos de búsqueda ya NO deberían
incluir `circuitBreaker` (porque "stop loss" no menciona streak/racha/pérdidas
