DISEÑO GENERAL (para tu contexto, no lo repitas en el código):
- Haiku, al terminar una síntesis de investigación (intent 'explain'), puede opcionalmente agregar una línea invisible con formato `<<SUGGEST_SONNET: resumen>>` SOLO cuando encontró un problema concreto y verificado — sea el que el usuario preguntó, o uno distinto encontrado de paso.
- El backend intercepta esa línea antes de mostrarla, la limpia del texto visible, y emite un evento nuevo `suggest_sonnet` con el resumen.
- El frontend muestra un botón resaltado (violeta, acorde al tier de Sonnet) SOLO cuando llega ese evento — nunca por defecto.
- Al hacer click, el frontend manda una nueva request con `triggerSonnet: true` — el backend salta Groq/Haiku por completo, reusa el historial de exploración ya guardado, y corre la fase de Sonnet directo.
- Esto es ADICIONAL al auto-handoff que ya existe para pedidos explícitos de modificación (`intent === 'generate'`, ya arreglado con el fix del regex reflexivo) — no lo reemplaza. El botón cubre el caso de "Haiku encontró algo pero el usuario no lo pidió".

const SUGGEST_SONNET_RE = /<<SUGGEST_SONNET:\s*(.+?)\s*>>\s*$/s;

/** Extrae la señal invisible <<SUGGEST_SONNET: ...>> del texto de Haiku, si existe.
 *  Devuelve el texto limpio (sin la línea de señal) y el motivo, o null si no hay señal. */
function extractSonnetSuggestion(text: string): { cleanText: string; reason: string | null } {
  const match = text.match(SUGGEST_SONNET_RE);
  if (!match) return { cleanText: text, reason: null };
  return { cleanText: text.slice(0, match.index).trimEnd(), reason: match[1].trim() };
}
