# PROMPT PARA REPLIT — Diagnóstico: por qué isCloned(repo) devuelve false para Signal OS

## Contexto

Acabamos de unificar la búsqueda de FAST/CHAT/DEEP sobre `unifiedGrepSearch`, que
depende de `isCloned(repo)` (en `services/localRepos.ts`) para decidir si usa ripgrep
local o cae al fallback de GitHub API.

Ya confirmamos por sync manual que el repo Signal OS SÍ está clonado en disco
(`/data/repos/Ahorar/.git` existe — la carpeta se llama `Ahorar`, ver `ALL_REPOS` en
`localRepos.ts`). Sin embargo, al correr una búsqueda en FAST mode con el selector de
repo puesto en "Signal OS (Ahorar)", el log mostró:

```
☁️ Repo no clonado aún — buscando vía GitHub API
```

Es decir, `isCloned(repo)` devolvió `false` a pesar de que el clon existe.

`isCloned` es simple y directo:

```typescript
export function isCloned(repo: string): boolean {
  try { return fs.existsSync(path.join(repoDir(repo), '.git')); }
  catch { return false; }
}
```

Esto significa que el string `repo` que le está llegando a esta función en tiempo de
ejecución probablemente NO es exactamente `"Ahorar"` — puede tener mayúsculas
distintas, espacios, el label completo del selector ("Signal OS (Ahorar)"), o algún
otro formato que no coincide con el nombre real de la carpeta clonada.
