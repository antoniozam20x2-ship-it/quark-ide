# Contexto para Replit — Gap #1: Edición directa sin JSON

## Quién soy y qué estoy construyendo

Estoy desarrollando **QUARK IDE**, un IDE personal deployado en Railway con backend Node.js/TypeScript y frontend React. El módulo clave para esta pregunta es el **Quark Agent** (`backend/src/routes/agent.ts`).

## Cómo funciona el Agent hoy

El Agent tiene dos modos que comparten memoria:

- **Fast Mode (Groq)**: Lee el archivo de GitHub, detecta el problema, identifica las líneas exactas a corregir.
- **Deep Mode (Claude)**: Recibe el contexto de Fast Mode y genera el fix.

El problema está en **cómo Deep Mode devuelve el fix**: actualmente le pedimos al modelo que devuelva el archivo **completo corregido** dentro de un JSON string así:

```json
{
  "files": [
    {
      "path": "backend/src/routes/chat.ts",
      "content": "...archivo completo con 300+ líneas escapadas..."
    }
  ],
  "commitMessage": "fix: descripción"
}
```

Esto es frágil. Si el archivo tiene 300–500 líneas, el modelo tiene que escapar correctamente cada `"`, `\n` y backtick dentro del string. Cuando falla, el JSON se rompe y entramos al `repairJSON` de emergencia (otra llamada al AI). Lo vemos como: `"el agente no pudo generar JSON válido"`.

## La mejora que quiero implementar

En vez de devolver el archivo completo, que Deep Mode devuelva **solo las operaciones de patch**:

```json
{
  "operations": [
    {
      "type": "str_replace",
      "path": "backend/src/routes/chat.ts",
      "old_str": "const GROQ_MODEL = 'llama-3.3-70b-versatile';",
      "new_str": "const GROQ_MODEL = 'llama-3.1-70b-versatile';"
    }
  ],
  "commitMessage": "fix: update groq model"
}
```

El backend aplica el `str_replace` sobre el contenido real del archivo (que ya tiene de GitHub), y hace el commit con el resultado.
