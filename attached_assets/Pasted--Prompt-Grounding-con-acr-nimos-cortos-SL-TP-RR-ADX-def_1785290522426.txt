# Prompt — Grounding con acrónimos cortos (SL, TP, RR, ADX...) + default seguro sin términos

**Por qué:** confirmado en producción — "Explícame el SL fijo" reutilizó un fragmento
cacheado sobre `placeTrailingStop` (turno anterior, tema distinto) y generó una
explicación inventada de "stop loss fijo" con ejemplo numérico ($100 → $95) que no
viene del código, citando la misma línea `autonomousAgent.ts:879` como si la respaldara.

Causa raíz — dos bugs relacionados:

1. `localKeywordFallback` descarta con `w.length > 4` cualquier palabra de 4 letras o
   menos. Eso incluye SL, TP, RR, ADX, RSI, EMA, ATR — el vocabulario más denso y más
   importante del dominio de trading. "SL" y "fijo" (4 letras) no sobreviven el filtro.
2. Con el resultado vacío, tres lugares del código usan el patrón
   `terms.length === 0 || terms.some(...)` — un array vacío hace que la condición sea
   `true` por el operador `||`. O sea: cuando no se pudo extraer NINGÚN término de la
   pregunta, el código interpreta eso como "está grounded" y confía en el fragmento
   cacheado sin haber verificado nada. El default correcto ante ausencia de evidencia
   es desconfiar, no confiar — mismo criterio fail-safe que ya usa
   `evaluateSearchConfidence` en otra parte del archivo ("preferir un salto extra de
   búsqueda antes que cortar información de más").

## Fix 1 — preservar acrónimos cortos en localKeywordFallback

```
En agent.ts, dentro de localKeywordFallback, agregá una categoría nueva para
acrónimos de 2-5 letras mayúsculas (SL, TP, RR, EMA, RSI, ADX, ATR...), y excluilos
del filtro genérico de "palabras largas" para no duplicarlos:

function localKeywordFallback(prompt: string, max = 4): string[] {
  const words = prompt.split(/\s+/);
  const isCapsSnake = (w: string) => /^[A-Z][A-Z0-9]*(?:_[A-Z0-9]+)+$/.test(w);
  const isCamel     = (w: string) => /^[a-z][a-z0-9]*[A-Z][a-zA-Z0-9]+$/.test(w);
  const isSnake     = (w: string) => /^[a-z][a-z0-9]*(?:_[a-z0-9]+)+$/.test(w);
  const isShortId   = (w: string) => /^[A-Za-z]\d{1,2}$/.test(w); // S1, S6, T2...
  // Acrónimos cortos (SL, TP, RR, EMA, RSI, ATR, ADX...) — 2-5 letras mayúsculas.
  // Sin esto, w.length > 4 los descarta y el término más denso del dominio de
  // trading queda invisible para cualquier chequeo de grounding aguas abajo.
  const isAcronym   = (w: string) => /^[A-Z]{2,5}$/.test(w.replace(/[?.,;:!]+$/, ''));

  const ranked = [
    ...words.filter(isCapsSnake),
    ...words.filter(isCamel),
    ...words.filter(isSnake),
    ...words.filter(isShortId),
    ...words.filter(isAcronym),
    ...words.filter(w =>
      w.length > 4 &&
      !KEYWORD_STOPWORDS.has(w.toLowerCase()) &&
      !isCapsSnake(w) && !isCamel(w) && !isSnake(w) && !isShortId(w) && !isAcronym(w)
    ),
  ];
  return [...new Set(ranked)].slice(0, max);
}
```

## Consecuencia esperada — no es un efecto secundario, es el fix

Con este cambio, cuando una pregunta no tiene NINGÚN término reconocible (ni acrónimo,
ni camelCase, ni snake_case), el sistema ya no asume que el fragmento cacheado sirve —
fuerza una búsqueda nueva. Esto es más lento en ese caso puntual (poco frecuente: casi
toda pregunta de dominio real trae al menos un acrónimo o identificador), pero elimina
la posibilidad de alucinar sobre un tema distinto al cacheado. Es el mismo tradeoff que
ya aceptaste en `evaluateSearchConfidence` — preferir un salto extra de búsqueda antes
que una respuesta inventada.

**Nota — no toca `isDomainTermGrounded`:** ese es un bug distinto (el `return true`
cuando el término no está en `SIGNAL_OS_TRANSLATIONS`, que dejó pasar `"trailing stop"`
sin filtrar en el caso anterior). Este prompt no lo incluye a propósito — mejor un
cambio a la vez, verificado, que dos fixes mezclados en el mismo diff.

**Prueba de verificación:**
1. Preguntar "cómo funciona el stop loss" y esperar la respuesta.
2. En el MISMO turno de sesión, preguntar "Explícame el SL fijo" → debe DESCARTAR el
   fragmento cacheado de `placeTrailingStop` (porque "SL" ahora sí se extrae pero no
   aparece literalmente en ese fragmento) y disparar una búsqueda nueva — no debe
   repetir la explicación inventada con el ejemplo de $100→$95.
3. Confirmar en logs que aparece el mensaje de "buscando en archivos adicionales" (o

4. Probar una pregunta sin ningún término técnico (ej. "¿por qué?") inmediatamente

   puramente referencial" (Señal 3 de `isLikelyFollowUp`), que es independiente de este
   fix y no debería romperse.
